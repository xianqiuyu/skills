# 紫鸟 ECO 新手引导

## 目标与边界

帮助新手通过“选择平台 → 选择场景 → 查看示例 → 确认开始”形成第一个任务。一次只问一个问题。

本 Skill 只做引导，不执行店铺查询、业务 API、页面操作、RPA 或付费数据请求。真正执行时必须移交 `ziniao-cross-border-workflow`；不得自行复刻或猜测它的业务规则。

## 开始前

1. 当前会话已有刚刚成功执行 `zn-open-eco auth status` 的可信结果时复用，不重复检查；否则第一条 CLI 命令必须是：

   ```bash
   zn-open-eco auth status
   ```

2. 未授权或检查失败时停止引导，提示用户完成 Auth Key 配置；不要请求业务数据，也不要回显凭据。
3. 使用宿主环境提供的原生 Skill 发现能力，确认存在 frontmatter `name` 精确等于 `ziniao-cross-border-workflow` 的 Skill。宿主不支持原生 Skill 加载但可访问本地文件时，可按该 `name` 查找并完整读取其 `SKILL.md`。无法加载时停止并说明需要重新安装 Skills；不要使用固定绝对路径，也不要猜测后续命令。

## 判断入口

- 用户已经给出具体业务需求：跳过平台和场景菜单，按“移交执行”继续。
- 用户只给出平台：直接展示该平台的场景，不再询问平台。
- 用户尚未给出平台或具体需求：只询问平台，随后等待：

  ```text
  为了给你推荐第一个可以体验的任务，你主要经营哪个平台？

  1. 亚马逊店铺
  2. TikTok Shop 店铺
  3. 其他平台

  回复编号即可；如果暂时不确定，也可以直接告诉我你想做什么。
  ```

用户选择平台后再展示对应场景。不要同时追问平台、店铺、关键词、站点或时间范围。


## 移交执行

只有用户明确回复“开始”“执行”，或已经给出具体需求时，才使用宿主环境的原生 Skill 机制加载 `ziniao-cross-border-workflow`，并把以下上下文交给它：

- 用户的原始目标；
- 用户已选择的平台与场景；
- 用户确认的示例或自行提供的具体需求；
- 当前会话已确认的鉴权状态。

如果宿主没有原生加载机制，按“开始前”的文件回退方式完整读取并遵守该 Skill。加载失败则停止，不得直接调用展示的 Product Skill 或猜测内部路径。

“开始”只表示接受当前示例并进入正式流程；不得绕过总控 Skill 的店铺确认、平台与站点兼容性、紫鸟 App/浏览器连接、积分或费用提示、写操作确认和其他安全门禁。Product Skill 不可用或条件不足时如实说明，并由总控 Skill 给出安全的下一步。

## 信息边界

- 用户可看到场景和 Product Skill 展示名称，但无需理解或手动选择内部 Skill。
- 不展示 Auth Key、店铺内部 ID、Skill path、API 参数、内部安装路径或完整原始响应。
- 不因新手选择场景而承诺能力一定可用，不把推荐当成执行结果。
- 用户不想选择平台时，允许其直接描述需求；不要强迫完成菜单。
